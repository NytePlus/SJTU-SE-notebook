# 一、请你帮助同学们解答在设计和开发服务器端程序时遇到的下列问题：

1. E-BookStore的数据库服务器配置为：一个16核CPU，64GB内存，2块1TB硬盘，考虑到E-BookStore每天活跃用户数很多，高峰期并发用户数量会达到5000，同学们希望能够将默认的数据库连接池尺寸重新配置，请问，为了在满足用户需求的情况下减少数据库服务器多线程调度的开销，你觉得连接池尺寸英高是多大？为什么？

2. 在按照作业要求实现异步的消息订单处理时，为了能够获得服务器端的处理结果，前后端采用了WebSocket通信。同学们为了保持前后端双向通信，设计方案为：
1） 前端利用Kafka发送消息给后端，并创建与后端的WebSocket连接；
2） 后端处理订单后，通过WebSocket连接发送处理结果给前端；
3） 前端与后端维持WebSocket连接，以便未来发送或接收新的订单信息。
请问，这种使用WebSocket的方式是否合理？请详细说明理由。

3. 同学们为了确保多用户访问数据库的数据一致性，定义了若干事务。请问，在事务管理中redo log是物理日志还是逻辑日志？为什么？

4. 同学们在使用Redis进行缓存时，将书的数据放到了Redis中，因为书的库存在每次下订单后都会修改，所以涉及到对Redis频繁的写操作，为了避免这种情况，同学们做出了如下的设计：
将Book类中不会发生修改的属性，例如书名、作者和ISBN号，与会发生变化的属性，例如价格和库存，完全分离成两个类；
只将上述包含不会发生修改的属性的类的对象缓存在Redis中。
请问：你觉得这个设计方案的优点和缺点各是什么？



5. 在多线程编程中，我们会看到Java对诸如Vector之类的容器类型会通过Copy-on-write方式执行读写分离：如果执行的是写操作，则复制一个新集合，在新集合内添加或者删除元素；待一切修改完成之后，再将原集合的引用指向新的集合。请问，你觉得这种设计方式主要是应对什么场景？请详细解释为什么它可以应对这种场景。

6. 同学们开发了Web服务，让电子书店可以与其他系统进行互操作，但是在使用REST API还是GraphQL API上存在争执。请问，你认为什么场景应该使用GraphQL API而不是REST API？请详细说明理由。

7. 同学们将采用微服务架构重构在线书店，将整个在线书店的功能拆分为多个微服务进行单独部署，但是所有微服务共享后台同一个数据库。请问，这种设计是否合理？请详细说明理由。

# 二、 请你帮助同学们解答在配置和使用数据库，并进行系统优化时遇到的下列问题：

1. 在进行图书封面图片的存储时，上课给的案例是使用MongoDB来存储，但是同学们认为这种方式并不合理，而是应该使用MySQL的Blob类型的字段来存储图片。请问，你觉得同学们的这种观点是否正确？请详细说明理由。

mysql> CREATE TABLE t1(c1 CHAR(255), c2 CHAR(255), c3 CHAR(255), c4 CHAR(255), c5 CHAR(255), c6 CHAR(255), c7 CHAR(255), c8 CHAR(255), c9 CHAR(255), c10 CHAR(255), c11 CHAR(255), c12 CHAR(255), c13 CHAR(255), c14 CHAR(255), c15 CHAR(255), c16 CHAR(255), c17 CHAR(255), c18 CHAR(255), c19 CHAR(255), c20 CHAR(255), c21 CHAR(255), c22 CHAR(255), c23 CHAR(255), c24 CHAR(255), c25 CHAR(255), c26 CHAR(255), c27 CHAR(255), c28 CHAR(255), c29 CHAR(255), c30 CHAR(255), c31 CHAR(255), c32 CHAR(255), c33 CHAR(255)) ENGINE=InnoDB ROW_FORMAT=DYNAMIC DEFAULT CHARSET latin1;

mysql> CREATE TABLE t2(c1 TEXT(65535) NOT NULL) ENGINE=InnoDB CHARACTER SET latin1;
第一条语句所有字段加起来的长度远小于第二条语句的字段长度，请问为什么在这种情况下，第一条语句仍旧失败了，而第二条语句依然成功？
